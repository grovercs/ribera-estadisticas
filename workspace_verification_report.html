🔍Hallazgos y riesgos

  • Crítico
    Tablas ausentes referenciadas por RPC

    Las funciones get_store_dashboard_impagados y get_store_dashboard_payables leen de receivables y vendor_payables, que no existen en database/supabase_schema.sql. El dashboard de Next.js invoca ambas RPC, por lo que fallará en producción.

  • Crítico
    Tablas históricas no declaradas en el esquema

    El método syncHistorical() inserta en stats_historical_kpis, stats_historical_sellers, stats_historical_warehouses, stats_historical_families, stats_historical_clients y stats_historical_products, ninguna de las cuales aparece en el DDL de Supabase.

  • Alto
    Discrepancia de base imponible vs. importe con IVA

    El dashboard Laravel usa importe_impuestos (con IVA) para KPIs de venta. Las RPC de márgenes usan net_amount (sin IVA). La comparación directa entre dashboards puede no cuadrar al céntimo si no se documenta la diferencia conceptual.

  • Alto
    Clave de Supabase con formato no estándar

    frontend/.env.local contiene una NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY con prefijo sb_publishable_. Las claves JWT reales de Supabase comienzan con eyJ. Verificar si es un placeholder o una clave válida.

  • Medio
    Scratch desordenado y potencialmente sensible

    Existen más de 100 scripts de investigación en scratch/, algunos con rutas absolutas, CSVs y logs. Deben limpiarse antes de producción o añadirse a .gitignore.

  • Medio
    Dependencia de fechas del sistema en el sincronizador

    syncSales() usa date('Y') y strtotime($row->fecha_venta) para decidir recálculos históricos. Si fecha_venta es nula o inválida, puede generar advertencias o recálculos incorrectos.

  • Bajo
    Tests automatizados no visibles

    No se encontraron tests unitarios ni de integración para el sincronizador ni para las RPC. Se recomienda añadir tests de paridad numérica.

✅Recomendaciones priorizadas

1 Completar el esquema Supabase: añadir las tablas receivables, vendor_payables y las stats_historical_* al DDL, con sus índices y políticas RLS.
2 Documentar la base de cálculo: decidir si los KPIs de ventas se reportan con o sin IVA y alinear tanto el sincronizador, las RPC y el frontend.
3 Validar credenciales de Supabase: confirmar que la publishable key del frontend es válida y rotarla si es un placeholder.
4 Refactorizar syncHistorical(): separar la carga histórica en métodos más pequeños y asegurar que las tablas destino existen antes de ejecutar upserts.
5 Limpiar scratch/: conservar solo scripts reutilizables y de documentación; mover datos temporales a .gitignore o eliminarlos.
6 Añadir tests de paridad: automatizar la comparación de totales entre SQL Server y Supabase con tolerancia 0,00 € para los rangos críticos.
